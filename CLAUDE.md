# MyGame: Anomaly Bakery Tycoon

Roblox game synced with Studio by **Script Sync**. Read this file first, then open only the modules you need.

## Sync setup
Folders map to Studio services: `ServerScriptService/`, `ReplicatedStorage/`, `StarterPlayerScripts/` (= `StarterPlayer.StarterPlayerScripts`). In Script Sync, link each service to the `MyGame` root (not to its own subfolder, or Studio nests it and scripts don't show).
File types: `*.server.luau` = Script, `*.local.luau` = LocalScript, plain `*.luau` = ModuleScript. Never use `*.client.luau` in StarterPlayerScripts (runs twice).

## Ground rules
- The world, machines, buttons and all Tools are built from code. Don't build gameplay parts in Studio; the place file isn't in git.
- Every tunable number lives in `ReplicatedStorage/Shared/ConfigParts/<Feature>.luau`, read as `Config.<Name>` (`Shared/Config.luau` merges the parts; add a new part's name to its list).
- Keep modules small (about 300 lines max) and in the folder of their feature. Server modules require siblings as `require(Services.<Folder>.<Module>)` with `local Services = script:FindFirstAncestor("Services")`.
- All player actions are validated on the server (owner, distance, unlocked, not broken, rate limits).
- Prompts: create them only with `Prompts.Add(model, part, spec)` and never set `Enabled` yourself. A rule (`Show`) decides visibility; a Broken item shows only its Repair prompt; visible prompts on one part stack via `UIOffset`. Keys: E main, F fill (hold), R recipe, T on/off, G unload, Q repair (`Config.Prompts`). MCP screenshots don't show prompt UI; check `Prompts.Visible(model)` instead.
- Labels: every BillboardGui is `AlwaysOnTop`, `LightInfluence = 0`, short `MaxDistance` (`Style.Billboard` does this). Don't add labels that can stack on screen; reuse the machine's sign.
- Robux: `Core/RobuxShop` is the only place that sets `ProcessReceipt`. Game Passes go through `Core/GamePasses` (`Active` = owned and allowed: `RandomItems` passes like 2x Roll / Instant Roll need `LuckAllowed`). Gameplay earnings use `DataManager.EarnCash/EarnGems` (2x Cash / 2x Gems passes); Robux purchases use `AddCash/AddGems`. Paid things never change random odds; Luck is PolicyService-gated (fails closed).

## Shared (`ReplicatedStorage/Shared/`)
`Config` + `ConfigParts/*`, `PlotLayout` (fixed upgrades: building, recipes, oven upgrades, automation; bought from the Build shop's Upgrades tab), `BuildCatalog` (placeable items), `BuildRules` (grid placement rules), `Recipes`, `Rarity` (tiers up to Anomalous, Void, Celestial; ingredient traits, MakeCake; re-exports `CakeRolls`), `CakeRolls` (cake traits, mutations, RollBake), `CakeData` (CakeInfo ⇄ attributes), `RebirthDefs`, `Achievements` (definitions).

## Client (`StarterPlayerScripts/`)
`ClientController.local.luau` mounts everything, wires remotes and builds the right-side button column (`SideBar`: Build, Bag, Achievements, Rebirth, Settings). `UI/Audio` (applies the player's volumes to the sound groups, `Audio.Play` for UI sounds). `UI/HUD/` (currency, toasts, Clock (top-right day/night + mutation event timers), highlighter, anomaly banner, recipe preview), `UI/Panels/` (Bag + auto-delete, Shop, Achievements, Rebirth, MixGame, Settings: volumes, auto-roll pop-ups and which world labels show, saved in `Settings.MusicVolume/SfxVolume/AutoRollPopups/HideLabels`), `UI/Effects/` (RoofFade (fades a plot's `RoofPart`s on this client while the camera is above the ceiling and you are inside, or in Build mode), WorldLabels (hides the label kinds in `Config.LabelKinds` a player switched off: machine signs + bin labels, cake tags, customer/vehicle bubbles; broken machines keep their sign; restores the server's own Enabled value), RollReveal, RarityCutscene (Void blackout / Celestial white-out), Cutscene, WorldFX tag animations, ScreenShake), `UI/Hotbar/` (custom hotbar replacing Roblox's backpack bar: `Hotbar` slots/keys 1-9/overflow grid, `ItemIcon` 3D ViewportFrame icons + rarity look, `Tooltip`), `UI/Build/` (Build mode, B key: `BuildMode` state + input, `BuildGhost` ghost preview/grid/no-build overlay using `Shared/BuildRules` + the plot's `BuildReserved` attribute, `BuildMenu` shop panel (Kitchen / Decor / Upgrades tabs; only while browsing; it fills the right side under the clock, and while Build mode is on the HUD attribute `BuildActive` hides the side button column and the hotbar), a narrow hint bar above the hotbar, and the left-side selection card (selected item: upgrade, move, rotate, store), `BuildRows` shop rows + widgets). Build mode hides ProximityPrompts (`ProximityPromptService.Enabled`) because R/Q/X double as build keys.

## Remotes (`Config.RemoteNames`)
Server→client: `Notify`, `BuildSync`, `AnomalyStarted/Ended`, `Cutscene`, `ScreenShake`, `RollResult`, `BagUpdate`, `MixStart`, `AchievementSync/Unlocked`.
Client→server: `BuildAction`, `BagAction`, `Settings`, `MixSubmit`, `BuyGemItem`, `ShopAction`, `GamePassPrompt`, `Rebirth`, `DevResetData`, `DevPreviewRoll` (Studio).

## Player data (`Core/PlayerDataSchema`)
Cash, Gems, UnlockedUpgrades, ShieldCharges, BoostEndsAt, Stats (lifetime counters; achievements watch them), Bag, NextItemId, MixRecipe, GemUpgrades, Receipts, Settings (auto-delete), Storage, Build (Owned, Placed records, migration flags), Rebirths, Achievements, Broken. New field = add it to the schema; `reconcile()` fills old saves.

## Key flows
- Cake value: ingredients (rarity × traits) → mix grade → bake rolls (cake traits, mutation) → `PlotStats.SalePrice` when sold.
- Every bake ends in `Ovens.FinishBake` (fires `Baked`). Stats go through `DataManager.AddStat/MaxStat` → `StatChanged` → achievements.
- Fixed upgrades live in `plot.Items` (by upgrade id); placed items in `plot.Placed` (`<Id>_<uid>`, attributes `CatalogId`, `Kind`, `Uid`). Find machines with `BakeUtil.findMachine(plot, idOrName)`. `Broken`, `Visible`, `IsOven` are attributes.
- New bakeries come furnished: `Config.Build.Starter` (catalog id + plot-local X/Z) is placed once per save by `BuildMigration` (`Build.StarterGiven`, after the legacy passes); a taken spot goes to the build inventory.
- Building size: `Config.Building` (ConfigParts/Build); don't hard-code building edges. The bakery grows in `Stages` (start 60x48, Bigger Bakery I 90x72, II 120x96; `BuildRules.Stage`/`StageAreas`). Items that depend on size (Walls incl. tiles/fence, Awning, SecondFloor, GoldenShopfront, recipe posters) build one child model per stage tagged `Stage = n` (`perStage` in ItemBuilders); TycoonButtons shows only the owner's stage. Placement areas (`BuildRules.StageAreas`: inside the current walls + the full-width front patio) and no-build rects are per stage (BuildArea publishes `BuildStage` + `BuildReserved` on the plot). Old saves grow to fit their placed items.
- Automation = placed Auto-Bakers (no fixed automation upgrades, no annex). `Config.Building.BackLot` is the empty lot behind the bakery (MapBounds keeps it clear). Old saves: `BuildMigration` (`Build.MigratedAutoBakers`) refunds the old annex/line upgrades, returns hopper ingredients and gives one free Auto-Baker per old production line (+ a Cake Rack for Auto-Restock).

## Testing
- Stop the playtest, let Script Sync push the edits, start again (edits never reach a running test).
- Smoke test (Server view): `game.ServerStorage.DebugBridge:Invoke("SmokeTest", "Run", game.Players:GetPlayers()[1], true)` → OK/FAIL per step plus logged errors. It resets the dev save. Update its steps when an API changes.
- Call running services via `DebugBridge:Invoke("<Module>", "<Function>", ...)`; it finds any module by name. Tables returned through it are copies. `require()` from MCP gets a separate module copy.
- Client twin (Studio): `game.Players.LocalPlayer.PlayerScripts.ClientBridge:Invoke("<UIModule>", "<Function>", ...)` calls the running UI modules (e.g. `BuildMode.Toggle`, `BuildMode.Select(model)`). HUD overlaps: `require(PlayerScripts.UI.LayoutCheck).Check()` lists overlapping visible HUD pieces; it must return nothing in every state.
- Script Sync needs a moment: after editing, check the new source is in Studio (Edit view) before starting a playtest.
- `Config.DevMode` (Studio only): Cash/Gems top-up and a separate `Dev_<UserId>` save key. HUD "Reset my data" button (Studio only).
- Rarity effects: HUD "Test Void" / "Test Celestial" buttons (Studio only), or `DebugBridge:Invoke("DevTools", "PreviewRoll", player, "<TierName>")` for any tier. Visual only (nothing added to the bag).
- MCP screenshots don't show particles or always-on-top billboards.
- Art meshes live in `ServerStorage.Assets` in the place file (not git): press Ctrl+S after changing them. Smooth low-poly base shapes: `ServerStorage.Assets.Shapes.<RoundedBox|Cylinder|Ball>` (from `Art/Shapes/*.fbx`, built by `Art/blender/make_shapes.py`; see `Art/README.md`). `Style.RoundedBox/Cylinder/Ball` use them when present (not for very stretched sizes) and fall back to plain parts, so they may return a MeshPart: type results as `BasePart`. `Lighting.Technology` must be set in Studio by hand.
